# Debug: T15 Funnel timeout test output
**Originated during:** mcax-execute T15 Stage B final review
**Status:** fixed

## Symptom

After the bounded helper implementation, the exact-child timeout probe completed successfully but Windows PowerShell 5.1 emitted a module first-use progress record as CLIXML on stderr, and the companion static test required one particular `TimedOut` property expression instead of the equivalent explicit result branches.

## Independent RED evidence

- Before production changes, both tests failed: the helper had no timeout parameter and the injected Node helper survived until the outer 10-second test timeout.
- The exact RED-owned process was identified by its unique `PROBE_PID_FILE` command line, killed by exact PID, and its absence was verified.
- After production changes, the timeout behavior completed in under one second with status 0, proving the helper settled; stderr contained only `Preparing modules for first use` CLIXML generated by harness cmdlet auto-loading.
- The static failure showed both `TimedOut = $true` and `TimedOut = $false` in the production result branches, while the assertion required only `TimedOut = $TimedOut`.
- The first full focused rerun exposed an older assertion that prohibited every `.Kill()` call. That contradicted the new requirement to terminate the exact timed-out helper even though the worker itself was still never hard-killed.

## Root cause

The remaining failures were test-shape issues, not production defects. `Get-Content`, `ConvertFrom-Json`, and `Get-Process` in an encoded Windows PowerShell 5.1 harness can auto-load modules and serialize progress records to the native stderr stream. The property assertion over-specified an implementation expression rather than the required result contract.

## Fix

The behavior harness uses only .NET file/process APIs and writes its small result directly, avoiding module auto-loading. The static assertion requires both explicit timeout result values. Production timeout, exact-process kill, output suppression, and Funnel cleanup logic are unchanged.

The legacy lifecycle assertion now prohibits `CloseMainWindow` and `$Worker.Kill()` specifically, while the new test separately proves the trusted helper kills only its exact `Process` instance and never scans or kills by name.
